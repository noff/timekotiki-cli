# Research: Генерация тайм-кодов из видеоролика

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Date**: 2026-10-31

Все пункты Technical Context разрешены; открытых NEEDS CLARIFICATION нет.

## R1. Движок распознавания речи

- **Decision**: `faster-whisper` (CTranslate2). Модель по умолчанию `large-v3-turbo`,
  `compute_type="int8"` на CPU, `float16` на CUDA при наличии. Включён `vad_filter=True`.
  Язык определяется автоматически (`info.language`), его можно задать флагом `--speech-language`.
  Модель загружается с `local_files_only=True`: при генерации сеть не используется.
- **Rationale**: Хорошее качество на русском и английском, тайм-стампы на уровне сегментов,
  колёса без компилятора для macOS, Linux и Windows. По публичным бенчмаркам это в 2–4 раза
  быстрее `openai-whisper` на CPU. VAD отбрасывает тишину и паузы, что закрывает edge case
  «длинные паузы в стриме» и даёт сигнал «речь не обнаружена».
- **Alternatives considered**: `openai-whisper` (PyTorch, тяжёлый, медленный на CPU);
  `mlx-whisper` (быстрый на Apple Silicon, но только macOS: нарушает требование поддержки
  Linux); `whisper.cpp` (нужна отдельная сборка или установка бинарника); Vosk (заметно
  хуже на свободной речи).
- **Модель как параметр**: `--asr-model` (`large-v3-turbo` | `medium` | `small` | …) —
  рычаг для слабых машин при риске по SC-003.

## R2. Декодирование и проверка входного файла

- **Decision**: использовать PyAV (`av`), транзитивную зависимость faster-whisper. Она
  объявляется явно, потому что используется напрямую. `media.py` открывает контейнер,
  проверяет наличие аудиопотока и берёт длительность. Декодирование в 16 кГц mono выполняет
  `faster_whisper.decode_audio`.
- **Rationale**: Системный ffmpeg не нужен, а PyAV поддерживает MP4, MKV, MOV, WebM, MP3,
  WAV и M4A. Ошибки открытия различаются: файл не найден или не читается (код 3), формат
  не поддерживается или файл повреждён (4), нет аудиопотока (5).
- **Память**: декодированное аудио 4 ч × 16 000 × 4 байта ≈ 0,9 ГБ. Модель turbo int8 занимает
  около 1 ГБ, LLM в Ollama работает в отдельном процессе (около 5 ГБ). В сумме это укладывается
  в бюджет SC-006 (16 ГБ) без потоковой обработки, так что YAGNI.
- **Alternatives considered**: subprocess к системному `ffmpeg`/`ffprobe` (лишняя внешняя
  зависимость и разбор вывода).
- **URL на входе**: если аргумент начинается с `scheme://`, команда отказывает с кодом 3
  и сообщением «only local files are supported».

## R3. Локальная LLM для разбиения и заголовков

- **Decision**: Ollama, HTTP API на `127.0.0.1:11434` через `urllib.request` из stdlib.
  Модель по умолчанию `qwen2.5:7b-instruct` (около 4,7 ГБ, q4), задаётся `--llm-model`.
  Используется `/api/chat` со structured outputs (`format`: JSON Schema), `temperature=0`
  и фиксированным `seed` для воспроизводимости.
- **Loopback-only**: хост берётся из `OLLAMA_HOST` (по умолчанию `127.0.0.1:11434`). Если он
  резолвится не в loopback (`127.0.0.0/8`, `::1`), команда отказывает с кодом 6 и объяснением.
  Так обеспечивается FR-016: данные не покидают машину.
- **Rationale**: Qwen 2.5 7B уверенно пишет на русском и английском и соблюдает
  JSON-схему. Ollama даёт Metal- и CUDA-ускорение и управляет моделями (`pull`, `list`)
  без Python-зависимостей.
- **Alternatives considered**: `llama-cpp-python` (сборка из исходников на части платформ
  противоречит Tech Constraints); `transformers` (PyTorch, медленно на CPU);
  TextTiling или эмбеддинги без LLM (не дают заголовков).
- **Недоступность**: если Ollama не запущена (connection refused) или модели нет
  (`/api/show` → 404), команда отказывает с кодом 6 и подсказкой (`ollama serve` или
  `timekotiki models pull`).

## R4. Алгоритм разбиения на разделы

- **Decision**: двухпроходная схема с детерминированной постобработкой.
  1. **Окна**: сегменты расшифровки группируются в окна по 10 минут с перекрытием 1 минута.
     Каждый сегмент подаётся строкой `[i] mm:ss текст`.
  2. **Проход A, границы**: для каждого окна LLM возвращает
     `{"boundaries": [{"segment": i, "topic": "..."}]}` — индексы сегментов, с которых
     начинается новая тема. В промпте есть ориентир «тема обычно длится 3–15 минут».
  3. **Слияние**: границы из перекрытий ближе 30 с друг к другу схлопываются в одну (берётся
     более ранняя), затем добавляется граница на сегменте 0.
  4. **Постобработка** (`postprocess.py`, без LLM, полностью unit-тестируемая):
     - начало главы привязывается к `start` сегмента, первая глава начинается в 0.0;
     - главы короче `--min-chapter` (по умолчанию 60 с) сливаются с предыдущей, а первая
       глава — со следующей;
     - пока число глав больше `--max-chapters`, сливается пара соседей с наименьшей
       суммарной длительностью;
     - если глав меньше 3 или какая-то короче 10 с, выводится предупреждение в stderr
       о правилах видеоплатформ (это не ошибка).
  5. **Проход B, заголовки**: для каждой итоговой главы LLM получает её текст (не более
     6000 символов: начало и равномерная выборка) и целевой язык, а возвращает
     `{"title": "..."}`. Заголовок обрезается до 60 символов по границе слова.
- **Rationale**: Окна решают проблему контекста на 4-часовых роликах (около 60 тыс. токенов
  расшифровки). Ограничения FR-004 и FR-009 выполняются кодом, а не надеждой на LLM.
  Проход B даёт единый язык заголовков (FR-010) и корректные заголовки после слияний.
- **Alternatives considered**: подать всю расшифровку целиком (не влезает в контекст 7B-модели
  и стоит дорого по префиллу); одна LLM-стадия без постобработки (FR-004 и FR-009 нельзя
  гарантировать); сегментация по эмбеддингам (ещё одна модель и всё равно нужна LLM для
  заголовков).
- **Кэш LLM**: не делается (YAGNI). Повторный запуск из кэша расшифровки — это только LLM:
  для часового ролика около 6 окон и около 10 заголовков, по оценке меньше 1 минуты на
  Apple Silicon (SC-004).

## R5. Кэш расшифровок

- **Decision**: ключ — SHA-256 содержимого файла (потоковое чтение блоками по 1 МБ) плюс
  `asr_model` и `speech_language` (или `auto`). Файл кэша:
  `<cache_dir>/transcripts/<sha256>.<asr_model>.<lang>.json` с полем `format_version: 1`.
  Расположение `cache_dir`: `$TIMEKOTIKI_CACHE_DIR`, иначе `$XDG_CACHE_HOME/timekotiki`
  (Linux), `~/Library/Caches/timekotiki` (macOS) или `%LOCALAPPDATA%\timekotiki\Cache`
  (Windows). Определение места — около 15 строк кода без `platformdirs`.
- **Поведение**: при несовпадении `format_version` или битом JSON запись игнорируется и
  перезаписывается. `--no-cache` пропускает чтение, но свежий результат записывает.
  `timekotiki cache clear` удаляет каталог `transcripts/`. Запись атомарная: временный файл
  в том же каталоге, затем `os.replace`.
- **Rationale**: Хэш содержимого выполняет FR-012 и US4/AC2: изменившийся файл даёт другой
  ключ. Хэш 4-гигабайтного файла считается за несколько секунд, на фоне распознавания это
  пренебрежимо.
- **Alternatives considered**: ключ по (путь, размер, mtime) не ловит изменение содержимого
  при сохранённом mtime и ломается при переименовании; SQLite избыточен для key → blob.

## R6. Форматы вывода и тайм-коды

- **Decision**:
  - Тайм-код: секунды отбрасываются вниз (floor) до целых. До 3600 с формат `MM:SS`, начиная
    с 3600 с — `H:MM:SS` (буквально по FR-005). `00:00` всегда первый.
  - `text` (по умолчанию): строки `<timecode> <title>\n`.
  - `json`: документ по [contracts/result.schema.json](contracts/result.schema.json).
  - `vtt`: `WEBVTT`, затем cue на каждую главу `HH:MM:SS.mmm --> HH:MM:SS.mmm` (до начала
    следующей главы или до конца видео) и заголовок.
  - Выбор формата: `--format {text,json,vtt}`, где `--json` равносилен `--format json`.
- **Rationale**: Текст вставляется в описание YouTube как есть (SC-005). JSON выполняет
  принцип II, WebVTT — FR-008.

## R7. Интерфейс CLI, прогресс, коды выхода

- **Decision**: `argparse` с подкомандами `generate`, `models {status,pull}` и `cache clear`.
  Сообщения CLI на английском. Заголовки глав пишутся на языке, выбранном по FR-010.
- **Прогресс**: этапы `probe → transcribe → segment → title` выводятся в stderr. В TTY это
  обновляемая строка с процентом (для распознавания процент считается по времени последнего
  сегмента относительно длительности ролика). Вне TTY выводится одна строка на этап, `--quiet`
  отключает вывод. Цвета не используются, поэтому `NO_COLOR` выполняется автоматически.
- **Коды выхода**: зафиксированы в [contracts/cli.md](contracts/cli.md) (0, 2–8, 130).
- **Прерывание**: `KeyboardInterrupt` → код 130. Временные файлы удаляются в `finally`, а
  `os.replace` гарантирует, что целевой файл либо старый, либо новый.
- **Rationale**: stdlib (принцип V). Подкоманды отделяют разовую загрузку моделей (`models
  pull`, единственная сетевая операция) от генерации.

## R8. Загрузка моделей (FR-015)

- **Decision**: `timekotiki models pull` скачивает ASR-модель через
  `faster_whisper.download_model` в стандартный кэш Hugging Face и LLM через Ollama
  `/api/pull` с потоковым прогрессом. `timekotiki models status` проверяет обе модели
  локально (`local_files_only`, `/api/show`) без сети и выдаёт таблицу или `--json`.
- **Rationale**: Сеть используется только по явной команде. Генерация при отсутствии модели
  завершается кодом 6 с точной командой для исправления.

## R9. Стратегия тестирования

- **Decision**:
  - **Unit**: `formats`, `postprocess`, `segmentation` (слияние окон), `cache`, `fsutil`,
    `media` (на сгенерированных `wave`-файлах: тишина, без аудио — `.txt`, битый файл).
  - **Contract**: валидация `--json` по схеме (через `jsonschema` только в dev-зависимостях),
    snapshot-тесты text и VTT, таблица «ошибка → код выхода», стабильность `--help`.
  - **E2E**: `cli.main(argv, deps=FakeDeps)` с фейковыми `Transcriber` и `ChapterModel`
    проверяет stdout, stderr и exit code по всем acceptance-сценариям. Subprocess-смоук
    `python -m timekotiki --help` и сценарий с отсутствующим файлом.
  - **Integration** (`-m models`, вручную или в отдельном CI-джобе): реальная цепочка на
    фикстуре речи RU около 30 с (OGG Opus, около 100 КБ, запись автора) и на эталонном
    наборе SC-001 вне репозитория (путь в `TIMEKOTIKI_BENCH_DIR`).
- **Rationale**: Детерминированные тесты без моделей выполняют принцип I. Качество (SC-001,
  SC-002) и скорость (SC-003, SC-004, SC-006) проверяются отдельным бенчмарк-скриптом
  `scripts/bench.py`.

## R10. Риски

| Риск | Влияние | Митигация |
|------|---------|-----------|
| SC-003 не выполняется на слабых Linux-ноутбуках без GPU | Медленное распознавание | `--asr-model small/medium`; бенчмарк в quickstart; цель зафиксирована для M-серии и сопоставимых CPU |
| LLM нарушает JSON или возвращает индексы вне окна | Падение прохода A | Structured outputs + валидация; невалидные индексы отбрасываются; при пустом ответе окно не даёт границ |
| Качество заголовков 7B-модели (SC-002) | Ручная правка | `--llm-model` для более крупной модели; промпт с примерами; оценка на эталонном наборе |
| Конституция v1.0.0 не про этот домен | Спорные гейты | Амендмент до `/speckit-tasks` (см. plan.md) |
