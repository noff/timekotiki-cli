# Feature Specification: Генерация тайм-кодов из видеоролика

**Feature Branch**: `001-video-timecodes`

**Created**: 2026-10-31

**Status**: Draft

## Clarifications

### Session 2026-10-31

- Q: Источник видео — только локальный файл или также ссылка? → A: Только локальный файл
  (видео или аудио).
- Q: Где выполняется обработка — локально или в облачном AI-сервисе? → A: Полностью локально.

**Input**: User description: "CLI-приложение для генерации тайм-кодов из видеоролика"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Получить список тайм-кодов для видео (Priority: P1)

Автор видео (например, записи лайвкодинга или доклада) запускает команду, указав свой ролик.
Приложение анализирует речь в видео, делит его на смысловые разделы и выводит список
тайм-кодов с короткими заголовками в формате, который можно сразу вставить в описание ролика
на видеоплатформе:

```text
00:00 Вступление
04:12 Настройка проекта
17:45 Пишем парсер
1:02:30 Итоги и вопросы
```

**Why this priority**: Это основная ценность продукта: автор экономит десятки минут ручного
просмотра и разметки. Без этой истории остальные не имеют смысла.

**Independent Test**: Запустить команду на эталонном ролике с заранее известной структурой
и убедиться, что выведен корректный список тайм-кодов, начинающийся с `00:00`, и границы
разделов совпадают с эталонной разметкой в пределах допуска.

**Acceptance Scenarios**:

1. **Given** видеофайл с речью длительностью 30 минут, **When** пользователь запускает
   генерацию, **Then** в стандартный вывод печатается список тайм-кодов в хронологическом
   порядке, первый тайм-код `00:00`, у каждого есть непустой заголовок.
2. **Given** видео длиннее часа, **When** генерация завершена, **Then** тайм-коды после
   первого часа выводятся в формате `Ч:ММ:СС`, до первого часа — `ММ:СС`.
3. **Given** генерация идёт долго, **When** пользователь смотрит в терминал, **Then** он видит
   индикатор прогресса в потоке ошибок (stderr), а stdout содержит только результат.
4. **Given** файл не существует или не содержит звуковой дорожки, **When** пользователь
   запускает генерацию, **Then** выводится понятное сообщение об ошибке в stderr и команда
   завершается с ненулевым кодом, специфичным для этого класса ошибки.

---

### User Story 2 - Машиночитаемый вывод и сохранение в файл (Priority: P2)

Пользователь, который автоматизирует публикацию роликов, получает тайм-коды в формате JSON
или сохраняет результат в файл, чтобы передать его другим инструментам (скрипту загрузки,
видеоредактору, плееру).

**Why this priority**: Делает инструмент встраиваемым в скрипты и пайплайны (требование
конституции о `--json`), но базовая ценность доступна и без этого.

**Independent Test**: Запустить генерацию с флагом `--json` и проверить, что вывод валиден
по документированной схеме и содержит те же разделы, что и текстовый вывод.

**Acceptance Scenarios**:

1. **Given** видеофайл, **When** пользователь запускает генерацию с `--json`, **Then** stdout
   содержит JSON-документ со списком разделов (начало в секундах, отформатированный тайм-код,
   заголовок) и метаданными (длительность видео, язык речи).
2. **Given** видеофайл, **When** пользователь указывает путь для сохранения результата,
   **Then** результат записывается в файл атомарно, а существующий файл не перезаписывается
   без явного флага.
3. **Given** видеофайл, **When** пользователь выбирает формат главы для видеоплеера
   (например, WebVTT-главы), **Then** результат выдаётся в этом формате.

---

### User Story 3 - Настройка детализации и языка заголовков (Priority: P3)

Пользователь управляет тем, насколько подробной будет разметка: минимальной длительностью
раздела, примерным или максимальным числом разделов и языком заголовков.

**Why this priority**: Улучшает качество результата для разных типов роликов (короткий
туториал vs трёхчасовой стрим), но разумные значения по умолчанию покрывают большинство
случаев.

**Independent Test**: Запустить генерацию на одном ролике с разными значениями параметров и
убедиться, что ограничения соблюдены в каждом результате.

**Acceptance Scenarios**:

1. **Given** видео на 2 часа, **When** пользователь задаёт максимум 10 разделов, **Then** в
   результате не более 10 тайм-кодов.
2. **Given** пользователь задаёт минимальную длительность раздела 5 минут, **When** генерация
   завершена, **Then** ни один раздел (кроме, возможно, последнего) не короче 5 минут.
3. **Given** речь в видео на русском, **When** пользователь запрашивает заголовки на английском,
   **Then** все заголовки сформулированы на английском.

---

### User Story 4 - Повторная генерация без повторного распознавания (Priority: P4)

Пользователь, недовольный детализацией, перезапускает генерацию с другими параметрами, и
приложение не распознаёт речь заново, а переиспользует уже полученную расшифровку того же
файла.

**Why this priority**: Распознавание речи — самая долгая часть; повторное использование
делает подбор параметров быстрым. Это оптимизация, а не базовая функция.

**Independent Test**: Запустить генерацию дважды на одном файле с разными параметрами и
убедиться, что второй запуск значительно быстрее и не повторяет этап распознавания.

**Acceptance Scenarios**:

1. **Given** файл уже обрабатывался, **When** пользователь запускает генерацию повторно с
   другими параметрами детализации, **Then** этап распознавания пропускается.
2. **Given** файл изменился с момента прошлой обработки, **When** пользователь запускает
   генерацию, **Then** расшифровка строится заново.
3. **Given** пользователь хочет начать с нуля, **When** он указывает флаг игнорирования кэша,
   **Then** распознавание выполняется заново.

---

### Edge Cases

- Видео без речи (музыка, тишина, экранная запись без голоса): команда сообщает, что речь не
  обнаружена, и завершается с отдельным кодом ошибки, не выдавая пустой или выдуманный список.
- Очень короткое видео (меньше минуты) или видео с одной темой: выдаётся один раздел `00:00`
  с общим заголовком; пользователь предупреждается, что видеоплатформы обычно требуют минимум
  три раздела.
- Очень длинное видео (4+ часа): обработка завершается без исчерпания памяти, прогресс
  виден, а прерывание (Ctrl+C) не оставляет повреждённых файлов результата или кэша.
- Несколько языков в одном ролике: заголовки формируются на основном языке речи, если язык
  явно не задан.
- Длинные паузы и технические перерывы в стриме: не выделяются как содержательные разделы,
  если в них нет речи.
- Неподдерживаемый формат файла или повреждённый файл: понятная ошибка с указанием причины.
- Пользователь передал URL вместо пути к файлу: понятная ошибка о том, что поддерживаются
  только локальные файлы.
- Локальные модели не установлены или повреждены: генерация не начинается, выводится
  инструкция по их получению, отдельный код ошибки.
- Путь вывода указывает на существующий файл: без флага перезаписи команда отказывается и
  завершается с ненулевым кодом.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Пользователь MUST иметь возможность запустить генерацию тайм-кодов, указав
  путь к локальному видео- или аудиофайлу как аргумент команды. Загрузка по ссылке (URL)
  не поддерживается: пользователь скачивает ролик сам.
- **FR-002**: Система MUST извлекать речь из звуковой дорожки видео и строить расшифровку с
  привязкой ко времени.
- **FR-003**: Система MUST делить видео на смысловые разделы по содержанию речи и формировать
  для каждого краткий заголовок (не длиннее 60 символов).
- **FR-004**: Первый тайм-код MUST быть `00:00`; тайм-коды MUST идти строго по возрастанию и
  не выходить за длительность видео.
- **FR-005**: Текстовый вывод по умолчанию MUST иметь формат `ТАЙМКОД Заголовок` по одной
  строке на раздел, пригодный для вставки в описание ролика; тайм-коды — `ММ:СС` для видео
  короче часа и `Ч:ММ:СС` для разделов после первого часа.
- **FR-006**: Система MUST поддерживать флаг `--json` с документированной стабильной схемой.
- **FR-007**: Система MUST поддерживать сохранение результата в файл с атомарной записью и
  отказом перезаписывать существующий файл без явного флага.
- **FR-008**: Система MUST поддерживать как минимум один формат глав для видеоплееров
  (WebVTT chapters) помимо текстового формата и JSON.
- **FR-009**: Пользователь MUST иметь возможность задать минимальную длительность раздела и
  максимальное число разделов; значения по умолчанию: минимум 1 минута, без жёсткого
  максимума (число разделов определяется содержанием).
- **FR-010**: Пользователь MUST иметь возможность задать язык заголовков; по умолчанию —
  основной язык речи в видео (автоопределение).
- **FR-011**: Система MUST показывать прогресс по этапам (извлечение звука, распознавание,
  разметка) в stderr при работе в терминале и не выводить ничего лишнего в stdout.
- **FR-012**: Система MUST кэшировать расшифровку локально, привязывая её к содержимому файла,
  и переиспользовать её при повторных запусках; MUST поддерживать флаг игнорирования кэша.
- **FR-013**: Система MUST завершаться с документированными различными ненулевыми кодами
  для классов ошибок: файл не найден/не читается, нет звука или речи, неподдерживаемый формат,
  ошибка распознавания или разметки, конфликт при записи вывода, отсутствие локальных моделей.
- **FR-014**: Распознавание речи, разбиение на разделы и формирование заголовков MUST
  выполняться полностью локально на компьютере пользователя; видео, звук и расшифровка
  никуда не отправляются, облачные AI-сервисы не используются.
- **FR-015**: После однократной подготовки (получения локальных моделей) генерация MUST
  работать без доступа к сети. Если модели ещё не получены, система MUST сообщить об этом и
  указать, как их получить; загрузка моделей выполняется только по явной команде или флагу
  пользователя.
- **FR-016**: Система MUST NOT отправлять какие-либо данные (видео, звук, расшифровку,
  телеметрию) по сети.

### Key Entities

- **Видео (источник)**: файл, подаваемый на вход; характеризуется путём, длительностью,
  наличием звуковой дорожки и отпечатком содержимого (для кэша).
- **Расшифровка**: последовательность фрагментов речи с временем начала и конца и текстом;
  содержит определённый язык речи; кэшируется и привязана к отпечатку видео.
- **Раздел (глава)**: смысловой отрезок видео; время начала, отформатированный тайм-код,
  заголовок; разделы упорядочены и покрывают видео от начала.
- **Результат разметки**: упорядоченный список разделов плюс метаданные (длительность видео,
  язык речи, язык заголовков, использованные параметры детализации); сериализуется в текст,
  JSON или формат глав для плеера.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: На эталонном наборе из не менее 10 размеченных вручную роликов не менее 80%
  эталонных границ разделов находятся в пределах 30 секунд от сгенерированной границы.
- **SC-002**: Не менее 80% сгенерированных заголовков оцениваются автором ролика как точные
  или требующие лишь мелкой правки.
- **SC-003**: Автор получает готовые к публикации тайм-коды для часового ролика менее чем за
  15 минут с момента запуска на типичном ноутбуке, против 30–60 минут ручной разметки.
- **SC-004**: Повторная генерация для уже обработанного часового ролика с другими параметрами
  детализации занимает менее 1 минуты.
- **SC-005**: 100% результатов в текстовом формате принимаются видеоплатформой как главы без
  правки формата (первый тайм-код `00:00`, порядок по возрастанию).
- **SC-006**: Обработка 4-часового ролика завершается успешно, без аварийного завершения из-за
  нехватки ресурсов на ноутбуке с 16 ГБ памяти.

## Assumptions

- Основные пользователи — авторы видео (стримы лайвкодинга, доклады, туториалы), где структура
  ролика определяется речью ведущего; анализ визуального ряда (смена слайдов, сцен) вне
  рамок этой версии.
- Основной язык роликов — русский; английский также поддерживается; другие языки — по мере
  возможностей распознавания, без гарантий качества.
- Поддерживаются распространённые видеоформаты (MP4, MKV, MOV, WebM); также принимаются
  аудиофайлы (MP3, WAV, M4A), поскольку анализируется только звук.
- Ручное редактирование разделов внутри приложения не требуется: пользователь правит
  текстовый результат в любом редакторе.
- Публикация тайм-кодов на видеоплатформе (загрузка описания через API) вне рамок этой версии.
- Ограничения видеоплатформ на главы (минимум 3 главы, каждая не короче 10 секунд) учитываются
  как предупреждения, а не как жёсткие ошибки.
- Загрузка видео по ссылке (YouTube и т. п.) вне рамок этой версии; при необходимости — отдельная
  фича.
- Локальные модели распознавания речи и формирования заголовков занимают несколько гигабайт
  на диске; пользователь готов однократно их скачать. Качество заголовков ограничено
  возможностями локальных моделей, работающих на ноутбуке без специализированного GPU.
- Кэш расшифровок хранится в пользовательском каталоге данных по конвенциям платформы и
  может быть очищен пользователем.
